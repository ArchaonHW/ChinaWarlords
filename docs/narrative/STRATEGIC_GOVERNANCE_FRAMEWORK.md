# 《民國史詩》策略與治平治理框架

> 狀態：遊戲設計原則草案。本文把兩篇使用者提供的理論文章轉譯為敘事與玩法方向；文中的模型屬作者提出的規範性／概念性框架，不是已驗證的實證公式，也不構成歷史事實。

## 來源文章的共同主張

兩篇文章都要求把「能否取勝」放回更長期的政治與社會結果中評估。

第一篇〈從勝負到治平〉把成熟權力理解為行動能力與自我限制並存：權力不只要能執行，也要能選擇不做、停止、接受審查並修正。它提醒，非常措施若沒有啟動條件、使用範圍、審查機制與退出條件，容易由例外變成日常制度。文章還以正當性、動員、制度化、修正、適應描述治理週期，並以安全、正當性、信任、韌性、適應力作為理解長期存續的觀察面向。

第二篇〈從三民主義到天下治平〉將民族主義、民權主義、民生主義重構為互相依存的治理原則，並連結民主問責、權力自制、民生保障和和平合作。文章把這套延伸稱作當代的規範性詮釋，也明言全球治理部分不是孫中山已完成提出的制度方案；其數學表示是概念工具，尚未完成實證驗證。

因此，遊戲採取兩篇文章的問題意識，不把文章中的公式、五行詮釋或政治主張偽裝成中立史實，也不把它們直接變成可互相抵銷的總分。

## 對本專案的設計原則

### 1. 成功衡量從「擊敗對手」擴展至「共同體能否延續」

軍事結果仍是重要資訊，但不是唯一結局條件。章節可分別記錄：

- 安全：部隊、居民與交通線是否受到保護。
- 民生：糧食、醫療、住所、教育與生計是否維持。
- 正當性：決策是否有可理解的理由，是否承認受影響者的意願。
- 信任：承諾、記錄與公共程序是否可信。
- 韌性：危機後是否仍有恢復和接續能力。
- 適應力：政策是否根據新證據與回饋修正。

這些面向不先加權成單一「治平值」。軍事勝利不能抵銷平民傷亡或權利侵害；同樣地，治理敘事也不能抹去安全威脅與保護責任。

### 2. 玩家工具同時包含行動權與停止權

戰術和治理任務都應容許適時停止、撤退、停火、交涉、解除動員或改變計畫。遊戲可以讓拒絕不必要的交戰成為有效選擇；停止行動不等於消極，須讓玩家看見其保護了哪些人、保留了哪些制度或造成了哪些風險。

對 RTS 指揮與遊戲 AI 而言，每類高風險行動都應有明確的中止條件。AI 具備進攻或動員能力，也要能服從停止／撤退命令，並透過戰報說明決策依據。模擬仍須遵守 deterministic/headless 規範；此處是遊戲內決策設計，不是調整開發 Agent 權限。

### 3. 非常措施必須能被查核和終止

若章節情境要表現戒嚴、緊急動員或其他非常權力，劇本及玩法應交代四件事：

1. 為何啟動，以及依據什麼程序。
2. 影響範圍和期限為何。
3. 誰能提出異議或進行獨立審查。
4. 何時、如何解除，事後如何追究責任。

不能把緊急狀態做成永久加成，或把限制權利只呈現成沒有代價的效率工具。若歷史脈絡中權力未能退出，這應由史實與角色經驗呈現為制度代價，不可用任務獎勵洗白。

### 4. 三民主義成為觀點與制度問題，不是單一陣營的勝利條

在涉及三民主義的章節，三項原則可轉成不同但互相關聯的提問：

| 原則 | 劇情／玩法提問 | 設計界線 |
|---|---|---|
| 民族主義 | 政治共同體如何獲得自主、承認內部多元並與其他群體平等相處？ | 不將民族自主等同於擴張、同化或支配其他群體。 |
| 民權主義 | 人民如何參與、監督、申訴、制衡並和平更換掌權者？ | 不把領袖自稱代表人民當成已獲得民主授權。 |
| 民生主義 | 發展、資源分配與基本生活如何兼顧公平及長期可持續？ | 不讓經濟成長或福利成果抹除權利受限與分配不均。 |

三項原則可以互相牴觸或失衡。故事要讓人物討論其實際代價，不由單一主角或一條「正確路線」替歷史下定論。這是文章對三民主義的當代詮釋；史實章節仍需提供多方政治立場及原始脈絡。

### 5. 把治理當成會回饋和修正的週期

文章的一個五階段治理比喻可轉成章節節奏：

**正當性形成 → 公共動員 → 制度建立 → 監督與修正 → 適應新條件**

這是設計用的週期模型，不是五行或歷史發展的科學定律。關卡可讓玩家看見前一階段留下的後果：動員如何轉為制度、制度如何處理錯誤、修正機制何時變成壓制、反思何時變成停滯。每一階段都應留下可追溯的檔案或角色證言。

### 6. 治平的方向是自願合作，不是更大的征服

全球治理、世界共和或「天下為公」只放在明確標示的可選推想篇章。正史主線不把世界統一、單一政府或任何現實政治方案設成必然終點。架空合作情境應以自由同意、平等參與、權利保障、自治和可問責為前提；若這些條件不足，就必須呈現權力集中和支配風險。

## 對應既有遊戲系統

目前 Campaign 已有可承接部分原則的機制：

- Campaign/Ledger/Ledger.h：append-only、雙式記帳與事件標籤，適合保留決策及其理由。
- Campaign/Governance/Accumulators.h：由帳本折算民心、秩序、墮落，不把治理值直接寫入模擬狀態。
- Campaign/Governance/Victory.h：已有治理勝利路徑，說明章節可不只以戰場勝負結算。
- Campaign/Aftermath/Aftermath.h：結算將戰鬥事件、傷亡與治理記錄一併處理，適合作為復盤入口。
- Campaign/State/CampaignState.h：可保存章節進度、帳本、世界、角色、情報與神話記錄。

目前程式實際追蹤的治理軸主要是民心、秩序、墮落；安全、信任、韌性、適應力尚未成為獨立狀態欄位。不要只因文章列出這些面向就新增五個數值欄。先以章節記錄和檢查清單驗證它們能否改善玩家理解，再決定是否有必要引入新資料模型。新資料若落地，必須使用既有 JsonValue、版本化 schema，並在壞資料被拒絕時保持原狀。

## 接回第一個主線切片

《黃花崗七十二烈士》將抽象原則轉為小型選擇：

- 傳遞命令、集結與保護行動代表「能力」。
- 停止追擊、選擇撤退路線、救援與保全檔案代表「限制及退出」。
- 戰後把史實、角色證言和原創對白分開，讓玩家審視自己的行動。
- 歷史起義結果保持不變；玩家改變的是局部救援、組織延續和記憶保存，不是誰在史實中勝出。
- 城隍、狐仙等內容只作可略過的輔線，不提供史實情報或改變戰果。

往後，《護法風雲》《寧漢分裂》《制憲與行憲》《風雨臺灣》等章節可逐步處理權力集中、政策修正、人民參與、權利保障和非常權力退出。每章仍要以當時史料決定可呈現的問題，不可為了套用模型而扭曲史實。

## 驗收檢查

未來實作玩法或章節時，逐項確認：

- 是否同時存在有效行動與合理停止／退出選項？
- 是否呈現安全、民生、正當性和權利之間的實際取捨？
- 是否避免用單一總分讓勝利抵銷侵犯或傷亡？
- 非常權力是否有啟動、範圍、審查和退出規則？
- 是否把文章的理論詮釋與史實及孫中山原始思想區分？
- 是否讓不同群體保有各自的證言與政治選擇？
- 戰役結果、模擬真相與存檔是否仍符合專案既有規範？
